Monthly Treasury Statement

The Monthly Treasury Statement (MTS), prepared by the U.S. Treasury's Bureau of the Fiscal Service, summarizes the federal government's receipts, outlays, and resulting budget deficit or surplus. It also reports financing activity and trust fund information, providing context for how money flows through government.

How often is it published?

Treasury publishes the MTS monthly, normally on the eighth workday of the month following the reporting month. Each release reports the preceding month's budget activity, with fiscal-year-to-date totals and comparisons where applicable. See Treasury's publication timing guidance.

What can you explore?

The nine numbered MTS tables covered by this site describe budget results and estimates, receipts by source, outlays by agency and function, financing, monthly trends, and trust fund activity.

Architecture and data flow

  1. Official source: the Treasury Fiscal Data API's mts_table_1 through mts_table_9 endpoints. Each download selects a report using record_date and retrieves all API pages for that date. The downloader can collect the latest report or a selected historical range.
  2. Collection and staging: a Python downloader, runnable in AWS Lambda or locally, assembles one JSON file per table. In AWS, files are stored in a private, versioned Amazon S3 bucket under mts/YYYY/MM/. A manifest records the report date, file keys, row counts, and SHA-256 checksums.
  3. Structured storage: a manually invoked AWS Glue Spark job validates the staged files and loads nine Apache Iceberg tables in Amazon S3 Tables, partitioned by record_date.
  4. Queries and exports: Amazon Athena queries the structured tables. An optional Glue export job selects the source and lineage columns into named CSV files without joins, filters, or aggregation. Separate tools support CSV export and loading into a local PostgreSQL database for analysis.
  5. Presentation: static HTML and CSS are configured for delivery from private S3 storage through Amazon CloudFront. The Net Income page embeds a separately published Tableau Public dashboard using MTS Table 4. Publishing or refreshing that dashboard is a separate step from downloading and loading reports.

Checks, reruns, and corrections

Before writing a report's data, ingestion checks that its manifest contains exactly nine tables and verifies file hashes, row counts, report dates, every row's columns, metadata types, and value conversions. It also checks target table schemas before replacing data. Unexpected schemas fail for review rather than silently changing the tables.

For each table, a successful load replaces the rows for that report date. Reruns avoid appending duplicate reports, and a revised report removes rows no longer present in its source. Other report dates remain intact. Each rerun creates new ingestion timestamps and table snapshots.

Replacement is atomic within each table, but there is no single transaction across all nine tables. A failed run can leave a partially updated report. Consumers should wait for the whole ingestion job to succeed; a complete rerun repairs a partial load. CSV exports likewise do not provide a single atomic publication across all nine files.

S3 versioning supports source inspection, but the staging template expires superseded object versions after 90 days. The downloader records hashes rather than pinning source version IDs in the manifest, so a historical manifest alone does not guarantee that its original source files can still be replayed.

Refresh, coverage, and analytical limitations

The staging template defaults to a monthly download on the 20th at 18:00 UTC, with a configurable schedule. The latest-report mode requires the previous month's report and fails if Treasury returns a different date. Lakehouse ingestion is manually invoked; this repository does not implement an automatic end-to-end refresh through dashboard publication. The table guides use an August 2026 reference snapshot; dashboard coverage must be checked in the dashboard itself.

MTS rows include headings, detail lines, subtotals, totals, and different reporting periods. Adding all rows can double-count amounts, and adding fiscal-year-to-date values across months can count the same activity repeatedly. Use the table guides to select the appropriate hierarchy level, period, and measure. Ingestion preserves Treasury's published net amounts and totals rather than recalculating them.

The Tableau workbook's calculations, filters, joins, unit formatting, and refresh history are not documented in this repository and have not been verified by this page. The preservation guarantees above apply to the collection and lakehouse stages. Dashboard-specific transformations need their own documentation before the same guarantees can be extended to a visualization.

This pipeline uses MTS financial data. USAFacts, linked below, is a separate resource rather than an input to this pipeline. The implemented ingestion does not link spending to legislation or establish the causal effects of policy.
